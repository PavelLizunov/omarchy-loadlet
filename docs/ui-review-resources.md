# UI review resources

Use the installed `omarchy-plugin-patterns` skill for native QML design review.
Its references/design-review.md, qml-visual-cycle.md and visual-review.md cover
hierarchy, icon meaning, stable geometry, state transitions and evidence.
The separate anti-slop skill exists in the local skill directory even though it
was absent from the abbreviated session catalog. Earlier claims that it was
unavailable were incorrect. Its carve-outs keep native Omarchy tokens and product
requirements above web styling defaults. No skill was installed by this follow-up.

## Public references

- [Impeccable](https://github.com/pbakaus/impeccable): design critique, hierarchy,
  cognitive load and common generated-UI patterns. Use its guidance as a reference
  for QML; its web detectors/hooks are not native-consumer evidence.
- [Growth.Design case studies](https://growth.design/case-studies): illustrated
  real-product flows, confusing choices, onboarding and ethical-design examples.
- [Nielsen usability heuristics](https://www.nngroup.com/articles/ten-usability-heuristics/):
  system status, recognition, consistency, error prevention and recovery.
- [Checklist Design](https://www.checklist.design/browse): component and flow
  checklists. Some pages are dynamic; the search snapshot did not expose the
  whole catalog, so no completeness claim follows.

These are references, not installed dependencies, proof of usability or authority
to run extra tests. The user's accepted native design remains the starting point.
A useful scoped review distinguishes navigation from actions, attaches controls
to their target, keeps unavailable data honest, and checks compact labels without
shrinking the primary content. A screenshot cannot establish keyboard behavior,
screen-reader support, hardware results or every state transition.
